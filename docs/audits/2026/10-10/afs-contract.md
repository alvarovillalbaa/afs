# AFS contract revision

Technical owner guides may keep established paths such as docs/references;
REFERENCES.md catalogs them. The validator rejects retired raw/source/goal/global
template surfaces without rejecting technical guide directories by name.

Source: owner's requested AFS changes, 2026-10-10.

The standard, website catalog, scaffolder, validator, templates, and harness
guidance now route management to AGENTS.md; references and provenance to single
root registries; goals to Notion; raw captures to the correct Google Drive; and
templates to their content owner. Knowledge is unique synthesis; continuous
research is organized into defined units.

Root instruction files stay at the repository root in the application profile.
Facts use living domain folders; decisions use decisions/. Retired root templates
and global raw/source/template/goal scaffolds are removed.

Application detection recognizes application manifests with a populated docs
shell while keeping instruction catalogs at the repository root. This prevents
application code directories from being classified as AFS intake.

Validation: four focused Node contract tests pass, covering application detection, fresh profiles,
existing-file preservation, URL capture, link rebasing, repeat runs, retained
unread raw data, and rejection of retired surfaces or undefined research units.
git diff --check and a focused TypeScript syntax check of the website catalog
pass. No dependency change, full build, deployment, or
cross-repository migration completion is claimed by this PR.

The migration command preserves ambiguous/external material and exits with an
explicit blocker. Verified external preservation and content-owner review are
required before removing those artifacts. Retained historical context must be
reviewed for obsolete routing; migration is not evidence of source ingestion.
